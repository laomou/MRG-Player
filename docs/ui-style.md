# 界面交互与绘制约定

这份文档记录 MRG Player 界面的**焦点模型**和**底部按钮条**的画法。改界面之前先读这里，
因为几个屏幕（书架、设置、核心页、管理抽屉、暂停菜单、对话框）共用同一套规则，改一处就得四处对得上。

## 1. 焦点只落在"容器"上

| 界面上是什么 | 能不能拿焦点 |
|---|---|
| 游戏卡片、胶囊按钮（LIBRARY / SETTINGS）、设置项行、分类栏、核心列表行 | 能 |
| 对话框的取消 / 确认按钮 | 能 |
| 底部按钮条的「选项 / 确定 / 返回 / 更改」 | **不能**（能点，但不进焦点序列） |
| 任何说明文字（副标题、描述行、键位提示） | **不能** |

规则可以一句话说清：**渲染成按钮或行（有底板、有边框、有高亮态）的东西才能获焦；
文字只是容器的标签，跟着容器一起高亮，自己不被方向键选中。**

判断一个元素该不该获焦，不要看文案（"确定""返回"和普通说明文字没有区别），要看它画成了什么。

## 2. 底部按钮条

每个屏幕最下面一条，右对齐，最多两项：**左边是选项/返回，右边是确定**。

它是**按钮**（鼠标点得到，点了就执行），但**不进焦点序列**：方向键永远留在内容里，按 ↓ 不会走到这一条，
它也不画焦点环。屏幕上唯一的高亮源始终是焦点所在的卡片或行。

- 一项 = 键徽章 + 动作词。键和词之间留 10px，两项之间留 22px。
- 键徽章是唯一的形状：单字符键画成圆（如 `A`），多字符键画成圆角矩形（如 `ENTER`），高 30px。
- **动作词只是文字**：没有底板、没有描边、没有辉光。给它加框会让屏幕底部多出一排盒子，
  和上面的内容抢视觉层级。
- 键和词的颜色恒定（深色底 + 亮色字），不随任何状态变化。
- 动作词一格一词，省掉屏幕已经说过的名词（书架上是 `X 选项`、核心页是 `ENTER 安装`）。
- 书架上没有"返回"这件事可放，所以两项是 X 选项 在左、确定在右，和别处"确定永远在右"的规则一致。
- 键盘/手柄不需要先移进来：A 就是启动选中的卡片，X 打开它的选项；设置页 ENTER 仍是更改当前行。
  鼠标点「返回」回书架，点「确定 / 更改」执行当前行。
- 没有可操作对象时（比如空书架，或焦点在顶部胶囊上），整条不画。
- **只有"自己不带返回/确认条目"的界面才有这条**：书架没有返回条目，设置页没有确认条目，所以这两处要画；
  暂停菜单（CONTINUE / RETURN HOME 就是条目）和管理抽屉（CANCEL 就是条目）不画，再在底下写一遍
  "ESC 返回 / ENTER 确认"是同一件事写第三遍。

## 3. 对话框

对话框**只有两个按钮**：左边取消，右边确认（确认按钮写具体动词，如 QUIT / REMOVE / POWER CYCLE）。

- **不带任何键位图标**：按钮上已经有字，再在下面重复一遍 `ENTER CONFIRM` 是同一件事写两遍，
  而且会把本来就不宽的框挤得更扁。这条对所有对话框都成立（退出、断电、删除存档、移除游戏）。
- 两个按钮都可聚焦、可鼠标点击；默认焦点在**取消**上（破坏性操作的安全默认）。
- 对话框之外的键位说明（如果有）一律走第 2 节的按钮条画法，不要另起一套样式。

## 3.1 抽屉与暂停菜单

管理抽屉和暂停菜单是**浮在画面中间**的卡片，不是通到底的长条：

- 面板高度 = 头部 + 内容行数（含分组间距），不预留底部页脚的高度；上下留白相等，卡片竖直居中。
- 条目只有标题（和可选的说明行），**不画键位图标**：图标要占一列固定宽度，会把标题挤歪。
- 抽屉打开时书架右上角的胶囊和页脚一起收起——模态层里没有可点的背景控件。

## 4. 所有页面统一的行为

1. 左 = 选项 / 返回，右 = 确定；书架按钮条、设置页按钮条、对话框按钮都是这个顺序。
2. 一屏一个焦点环，焦点变化时有 120ms 淡入，不闪。
3. 鼠标命中和绘制共用同一份几何（同一套 `*Layout()` 函数），不允许各算各的坐标。
4. 列表行（暂停菜单、管理抽屉、核心列表）自己不画键位图标；这些界面的条目里已经有 CANCEL / CONTINUE /
   RETURN HOME，或那一行本身就是可调的值，所以底部也不画按钮条。

## 4.1 屏幕上的键位由 PROMPT DEVICE 决定

界面上的每一个键徽章画的都是**玩家手上那颗键**，不是写死的键盘键。改哪一套由设置页的
`CONTROLLER → PROMPT DEVICE` 决定，三档：

| 档位 | 显示什么 |
|---|---|
| AUTO（默认） | 跟随最后一次用过的输入设备：按手柄就显示手柄键，动键盘鼠标就显示 `ENTER` / `ESC`；手柄被拔掉时回落到键盘 |
| KEYBOARD & MOUSE | 永远显示键盘键（`ENTER` / `ESC` / `LEFT/RIGHT` / `.`），插着手柄也不变 |
| CONTROLLER | 永远显示手柄键（`A` / `B` / `LB` / `D-PAD` …） |

注意三件事：

1. **设置只改标签，不改谁能操作。** 键盘和手柄始终都能操作所有界面，AUTO 只是决定哪一套字写在按钮上。
2. **手柄字母跟着 CONTROLLER STYLE 走**：`XBOX` 是 A/B/X/Y，`NINTENDO` 把 A↔B、X↔Y 换过来，
   `PLAYSTATION` 写 CROSS / CIRCLE / SQUARE / TRIANGLE，`AUTO` 按识别出的手柄品牌选，`GENERIC` 用编号。
3. **掌机（Brick）只有面板**：AUTO 从第一帧就解析成手柄，不会出现桌面键；就算在模拟器里按宿主键盘，
   事件也被固件翻成面板按键，标签不会跳回键盘。掌机插了键盘想让标签写 `ENTER`，手动选 KEYBOARD & MOUSE 即可。

游戏内的按键不归这条管：进游戏后按键直接交给核心的输入映射（见 README 的 Controls 一节），
PROMPT DEVICE 只影响启动器自己的界面。

## 5. 代码位置

| 东西 | 位置 |
|---|---|
| 按钮条的测量、绘制 | `src/ui/Primitives.cpp`（`actionWidth` / `actionLayout` / `drawActionRow`） |
| 书架按钮条 | `src/ui/HomeScreen.cpp`（`footerHints`、`homeActionAt`） |
| 设置页按钮条 | `src/ui/SettingsScreen.cpp`（`settingsFooterHints`、`settingsFooterAt`） |
| 焦点状态机 | `src/app/Application.cpp`（`HomeFocus`、`settingsNavigate`） |
| 键位提示的解析 | `src/config/InputBindings.cpp`（`resolvePromptDevice`、`inputPrompts`、`controllerButtonPrompt`） |
| 提示设备设置项 | `src/ui/SettingsScreen.cpp`（CONTROLLER 页的 PROMPT DEVICE 行） |
| 暂停菜单 / DISPLAY / CORE OPTIONS 卡片 | src/ui/PauseMenuScreen.cpp（pauseLayout） |
| 管理抽屉 | src/ui/GameManagementScreen.cpp（managementLayout） |
| 对话框 | `src/ui/HomeScreen.cpp`（退出）、`src/ui/PauseMenuScreen.cpp`（断电）、`src/ui/GameManagementScreen.cpp`（移除/删档） |

改样式时优先只改 `Primitives.cpp` 里的常量和 `drawAction`，四个屏幕会一起跟上。
